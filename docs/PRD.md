## 1) 목표와 성공조건

### 1.1 목표

사진 한 장으로 **오락 목적의 관상 해석 카드**를 즉석에서 제공하고, 사용자가 그 화면을 이미지로 다운로드하거나 SNS(카카오톡, 인스타그램, 트위터 등)로 직접 공유할 수 있게 한다.

### 1.2 범위 경계

| 구분 | 값 |
|---|---|
| 화면 | **1개** (상태 전환 방식, 페이지 이동 없음) |
| 기능 | **2개** — ① 사진 입력 → 관상 해석 출력, ② 결과 카드 이미지 생성 및 SNS 공유/다운로드 |
| 제외 | 로그인·결제·DB. 그 외 제외 항목 8개는 `00_BRIEF.md` §2 |

### 1.3 성공조건

지표 자체는 `00_BRIEF.md` §1에 정의돼 있다. 이 문서는 **각 지표를 어떻게 판정할지**만 정의한다.

| ID | 대응 지표 | 판정 방법 | 판정 시점 |
|---|---|---|---|
| S-1 | 완주율 | 지인 10명에게 링크만 전달(사용법 설명 없음) → 결과 화면 도달 인원을 직접 관찰·집계 (가정) | 배포 후 |
| S-2 | 응답 시간 | "분석 시작" 입력 시점 ~ 결과 카드 렌더 완료 시점을 실기기에서 3회 측정, 중앙값 15초 이내 (가정) | 배포 후 |
| S-3 | 자발적 공유 | 공유 수단(Web Share / 이미지 다운로드 / 링크 복사)을 통한 캡처·공유 발생 여부 확인 | 배포 후 |
| S-4 | 금지 표현 0건 | 결과 문구 표본을 §4.3 금지 표현 목록과 대조. (표본 30건 검증) | **배포 전** |

### 1.4 목표가 아닌 것

- **해석의 정확도·적중률** — 결과물은 오락물이며, 맞았는지 여부를 성공 지표로 삼지 않는다.
- **재방문·리텐션** — 1회성 소비를 전제로 한다.
- **대규모 트래픽 대응** — 지인 그룹 규모를 전제로 한다.

## 2) 사용자 스토리

| ID | 스토리 | 수용 기준 | 현황 |
|---|---|---|---|
| **US-01** | 링크를 처음 받은 사용자로서, 시작 전에 이 서비스의 성격과 내 사진 처리 방식을 알고 싶다. 그래야 사진을 올릴지 판단할 수 있다. | ① 동의 전에는 사진 선택 수단에 접근할 수 없다<br>② 고지에 3가지(오락 목적 / 사진 미저장 / 타인 사진 무단 업로드 금지)가 모두 포함된다<br>③ 동의는 명시적 행동(체크 또는 버튼)으로만 성립한다 | ✅ 구현 완료 (`ScreenConsent`) |
| **US-02** | 사용자로서, 내 기기의 사진을 골라 올리고 싶다. | ① 기기 사진 선택이 가능하다<br>② 선택한 사진을 전송 전에 화면에서 확인할 수 있다<br>③ 다른 사진으로 바꿀 수 있다 | ✅ 구현 완료 (`ScreenSelect`) |
| **US-03** | 사용자로서, 기다리는 동안 진행 중이라는 것을 알고 싶다. 그래야 멈춘 줄 알고 이탈하지 않는다. | ① 요청 직후 즉시 진행 중 표시가 나타난다<br>② 진행 중에는 중복 요청이 불가능하다 | ✅ 구현 완료 (`ScreenAnalyzing`) |
| **US-04** | 사용자로서, 결과를 한 화면에서 읽고 그대로 캡처하고 싶다. | ① 결과 전체가 세로 스크롤 1회 이내에 들어온다<br>② 결과 화면 안에 "오락 목적" 문구가 함께 보인다<br>③ 캡처를 방해하는 요소(모달, 자동 이동)가 없다 | ✅ 구현 완료 (`ScreenResult`) |
| **US-05** | 사용자로서, 실패했을 때 무엇이 잘못됐고 무엇을 하면 되는지 알고 싶다. | ① 모든 실패는 §4.3의 처리 중 하나에 해당한다<br>② 원인 안내와 다음 행동이 함께 제시된다<br>③ 기술 용어·에러 코드를 그대로 노출하지 않는다 | ✅ 구현 완료 (`ScreenError`) |
| **US-06** | 사용자로서, 다른 사진으로 한 번 더 해보고 싶다. | ① 결과·에러 화면에서 1회 조작으로 사진 선택 상태로 돌아간다<br>② 재시작 시 고지·동의를 다시 거치지 않는다 (같은 방문 내) | ✅ 구현 완료 (`page.tsx`) |
| **US-07** | 사용자로서, 내 관상 결과를 이미지 파일로 저장하거나 SNS(카카오톡, 인스타그램 등)로 친구들에게 바로 공유하고 싶다. | ① 결과 카드를 이미지 파일(PNG)로 직접 저장할 수 있다<br>② 모바일 공유 팝업(Web Share API)을 통해 카카오톡/인스타/X 등으로 즉시 전송할 수 있다<br>③ 링크 복사 기능을 제공한다 | ⏳ Sprint 3 구현 예정 |

## 3) 화면 명세

화면은 1개, 그 안에서 **5개 상태**가 전환된다. (`ScreenShell` 공통 래퍼 사용)

### 3.1 상태 전이

| 상태 | 진입 조건 | 사용자에게 보여야 할 정보 | 가능한 행동 | 다음 상태 | 현황 |
|---|---|---|---|---|---|
| **A. 고지·동의** | 최초 진입 | 서비스 이름·성격, 고지 3종, 동의 수단 | 동의 | A → B | ✅ 구현 완료 (`ScreenConsent`) |
| **B. 사진 선택** | A에서 동의 완료 | 사진 선택 수단, 선택 후 미리보기, 분석 시작 수단 | 사진 선택 / 사진 변경 / 분석 시작 | B → C | ✅ 구현 완료 (`ScreenSelect`) |
| **C. 분석 중** | B에서 분석 시작 | 진행 중 표시, 예상 소요에 대한 안내 | (없음 — 대기) | C → D 또는 C → E | ✅ UI 구현 완료 (`ScreenAnalyzing`) |
| **D. 결과** | 유효한 결과 수신 | 관상 해석 결과, 오락 목적 고지 재노출, 공유/다운로드/다시하기 수단 | SNS 공유 / 이미지 저장 / 링크 복사 / 다시하기 | D → B | ✅ 연동 완료 (공유 버튼 Sprint 3 고도화) |
| **E. 에러** | §4.3의 예외 발생 | 원인 안내 1줄, 다음 행동 | 재시도 또는 사진 다시 선택 | E → B, E → C | ✅ 구현 완료 (`ScreenError`) |

```
A(고지·동의) → B(사진 선택) → C(분석 중) → D(결과)
                   ↑                ↓           ↓ (SNS 공유 / 다운로드)
                   └────── E(에러) ←┘           │
                   └────────────────────────────┘
```

## 4) 기능 명세

### 4.1 기능 목록

| ID | 기능 | 설명 | 완료 판정 | 현황 |
|---|---|---|---|---|
| **F-01** | 사전 고지·동의 | 고지 3종을 표시하고 명시적 동의를 받는다. 동의 전 사진 선택 차단 | 동의 전 사진 선택이 불가능함이 확인됨 | ✅ 완료 |
| **F-02** | 사진 선택·미리보기 | 기기 사진 1장을 선택하고 전송 전 확인·교체 | 선택→교체→선택이 오류 없이 반복됨 | ✅ 완료 |
| **F-03** | 분석 요청 | 선택한 사진을 분석 엔진에 전달하고 구조화된 해석 결과를 받는다. **인증 정보는 사용자 기기에 노출되지 않아야 한다** | 결과 또는 §4.3의 정의된 예외 중 하나로 귀결됨 | ✅ 백엔드 연동 완료 |
| **F-04** | 결과 카드 렌더링 | 받은 결과를 카드 형태로 표시. 결과 항목 구성은 `03_ANALYSIS-SPEC.md` | 결과 항목 순회 렌더링 및 캡처 UI 구성 완료 | ✅ 완료 |
| **F-05** | 다시하기 | 결과·에러 상태에서 사진 선택 상태로 복귀 | 1회 조작으로 B 상태 진입 | ✅ 완료 |
| **F-06** | 사진 폐기 | 원본 사진을 어디에도 영구 저장하지 않고 분석 처리 직후 폐기 | 저장 경로가 코드상 존재하지 않음이 확인됨 | ✅ 완료 |
| **F-07** | 결과 카드 SNS 공유 및 저장 | 결과 카드를 Canvas 이미지로 변환 후 Web Share API를 통한 SNS 공유 및 이미지/링크 저장 기능 제공 | 원클릭으로 모바일 공유 팝업 호출 및 이미지 다운로드 동작 | ⏳ Sprint 3 진행 예정 |
